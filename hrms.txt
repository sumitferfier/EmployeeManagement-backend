Yes, this is an important design decision. We should clarify it before moving further.

The key question

When a person registers for the first time:

How does the system decide whether they are an ADMIN or an EMPLOYEE?

Recommended enterprise approach

The user should NOT choose ADMIN during public registration.

Instead:

First system setup
        ↓
Create initial ADMIN
        ↓
ADMIN logs in
        ↓
ADMIN creates/manages EMPLOYEE users
        ↓
Employees log in with their assigned accounts
Recommended HRMS flow
1. Initial Admin creation

When the application/database is set up for the first time:

Roles
├── ADMIN
└── EMPLOYEE

Then create the first admin account:

User
├── username: admin
├── email: admin@hrms.com
├── password: BCrypt hashed
└── role: ADMIN

This can be created through:

SQL script
Spring Boot startup seeder
Database migration

I recommend a Spring Boot Data Seeder for development.

2. Public registration

If you keep a Register page for normal users:

User fills registration form
        ↓
Backend receives username/email/password
        ↓
Backend automatically assigns EMPLOYEE role
        ↓
User is created

The frontend should not send:

{
  "roleName": "ADMIN"
}

Because anyone could modify the request and potentially attempt admin registration.

Instead:

{
  "username": "sumit",
  "email": "sumit@example.com",
  "password": "Password@123"

Backend:

Find EMPLOYEE role
        ↓
Assign it automatically
        ↓
Create user

One important detail

When an Admin changes a user's role:

EMPLOYEE → ADMIN

the user's old JWT token still contains the old role if your JWT stores the role as a claim.

Therefore, after changing a role, the user should:

Role Changed
     ↓
Old token should no longer be trusted / expire
     ↓
User logs in again
     ↓
New JWT generated
     ↓
New role is applied

User Management / Admin Role Assignment

Add an Admin-only endpoint like:

PUT /api/v1/users/{userId}/role

Request:

{
  "roleId": "role-uuid"
}

Only an ADMIN can call this API.

So yes: first Admin is seeded → normal users register → default Employee → Admin can later promote/demote users by assigning roles.
